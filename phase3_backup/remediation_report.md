## 2. Detailed Code Changes by File

### 2.1 `database_setup.py`
- Added `_enforce_untrusted_schema(conn)` which executes `PRAGMA trusted_schema = OFF;`, queries `PRAGMA trusted_schema;`, and raises `RuntimeError` if the integer read-back is not `0`.
- Updated `connect_sqlite()` to call `_enforce_untrusted_schema(conn)` immediately upon opening any SQLite connection before any schema query or `PRAGMA` inspection.

### 2.2 `prototype_shadow_migrate.py`
- **Bounded C-Level Online Backup (`_bounded_sqlite_backup`)**: Loaded `libsqlite3.so.0` (`libsqlite3.dylib` on macOS) via `ctypes`, extracted the raw `sqlite3*` pointer from CPython's `pysqlite_Connection` struct (verified via `sqlite3_db_filename`), and stepped `sqlite3_backup_step(backup_handle, pages_per_step)` inside a `time.monotonic()` deadline loop. When `rc in (SQLITE_BUSY, SQLITE_LOCKED)` exceeds `timeout_ms`, `sqlite3_backup_finish` is invoked immediately and `sqlite3.OperationalError("database is locked (bounded backup timeout exceeded)")` is raised.
- **Logical Database Digest (`compute_logical_db_digest`)**: Computes a canonical SHA-256 over all user tables (name, normalized DDL, row count, whole-table content SHA-256) and all non-table schema objects (`index`, `trigger`, `view` name, type, table, normalized DDL). Because it hashes logical relational state rather than raw page layout, passive or truncating WAL checkpoints never cause false CAS failures (`C-04`).
- **Per-Column Canonical Hashing (`_fingerprint_table_and_columns`, `TableSnapshot.column_sha256s`)**: Computes both the full-row SHA-256 digest and an independent SHA-256 digest for each column in a single streaming `cursor.fetchmany(1024)` pass on `shadow_db` before and after the migration. If a table's column list changes (e.g., `ALTER TABLE ... ADD COLUMN`), every shared column (`col in snap_before.column_sha256s and col in snap_after.column_sha256s`) is compared by its column-level SHA-256 (`D-01`), catching any silent value corruption in existing columns without re-reading `source_db`.
- **Zero-TOCTOU Promotion Protocol (`_promote_shadow_to_source`)**:
  1. Acquires an exclusive non-blocking POSIX flock (`fcntl.flock(lock_fd, fcntl.LOCK_EX | fcntl.LOCK_NB)`) on `<source_db>.litemigrate.lock` with bounded retry up to `busy_timeout_ms`.
  2. Creates a `0o600` pre-promotion rollback backup of `source_db` via `_bounded_sqlite_backup`.
  3. Opens `source_conn` and executes `BEGIN IMMEDIATE;` (acquiring SQLite's `RESERVED` writer lock so no external SQLite connection can start or commit a write transaction).
  4. Recomputes `live_source_digest = compute_logical_db_digest(source_conn)` **while holding `BEGIN IMMEDIATE`**. If `live_source_digest != expected_baseline_digest`, executes `ROLLBACK;` and raises `PermissionError`, returning `ValidationVerdict.BLOCKED_SOURCE_MODIFIED_CONCURRENTLY`.
  5. For SQL migrations, replays the validated statements directly inside the held `BEGIN IMMEDIATE` transaction on `source_conn`, verifies `PRAGMA foreign_key_check` and `PRAGMA quick_check` before `COMMIT`, and commits atomically (`P-02`).

### 2.3 `benchmark.py` and `test_shadow_migration.py`
- `benchmark.py` now runs dataset population and shadow migration/audit in separate `subprocess.run` invocations per scale (`10 MB`, `100 MB`, `500 MB`), reporting both `isolated_migration_peak_rss_mb` (`33.18 MiB` – `34.16 MiB`) and `setup_process_peak_rss_mb` (`22.87 MiB` – `33.05 MiB`).
- `test_shadow_migration.py` now tests `apply_to_source_on_pass=True` under concurrent writer contention (`test_07`) and asserts `CloneStrategy.LINUX_FICLONE` deterministically on Linux XFS (`test_10`).
